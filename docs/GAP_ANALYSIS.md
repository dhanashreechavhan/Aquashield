## Requirement-by-requirement status

| Requirement | Status in inspected code | Limit or dependency |
|---|---|---|
| Home dashboard | Present | Weather forecast calls Open-Meteo and falls back to a bundled CSV; it needs internet for live data. |
| Flood-risk map | Present | Shows 12 sampled locations and interpolated display; this is not a hydraulic inundation map. |
| Analytics | Present | Uses processed rainfall and rule-based labels. |
| ML model and evaluation | Present | Joblib classifier/regressor and temporal/spatial metrics are included. Labels are formula-generated proxies, not surveyed flood outcomes; excellent scores must not be presented as real-world flood accuracy. |
| Road-risk map | Present | Derived road segments and infrastructure-susceptibility scores; not current water-depth observations. |
| Safe routes | Partly present | Dijkstra weights a graph connected from nearby road midpoints. It is a demo approximation, not a validated street-by-street routable road network. Only recent verified user reports can raise edge costs; synthetic and unverified posts are ignored. |
| IoT monitoring | Present as simulation | No ESP32 or Firebase connection. The page labels readings as simulated. |
| Community photo/video reports | Present for a local demo | SQLite and media files live on this computer. There is no hosted/shared storage, authentication, or real moderation workflow. |
| YouTube Shorts | Present | 65 public records with embeds; inferred locations/severity are approximate and unverified. |
| Instagram posts | Partly present | Six manually catalogued records; no Instagram search/API integration. |
| Facebook posts | Demo only | Synthetic Facebook-style captions are community demo records, not Facebook data. |
| Phone/Play Store app | Not present | The deliverable is a responsive browser-based Streamlit application, not a packaged Android app. |
| Dataset ground truth | Limited | The files include four curated records for one major 18 July 2021 event. That is useful context, but too little independent event history to validate general flood-prediction skill. Most model labels are still generated by a rule-based formula. |

## Synthetic, observed, and user data

- Processed rainfall, elevation, and road tables are supplied as CSVs and tagged by source in the app where applicable. Their presence alone does not prove independent field validation.
- Flood-risk classes are rule-generated. The model learns those classes; it is not trained against a verified flood/no-flood survey set.
- Four seeded posts are explicitly synthetic demo posts. User uploads are stored separately from the social-video catalogue and official/curated events.
- YouTube/Instagram are public or manually catalogued media, not official alerts. Approximate pins and title-inferred severity are not evidence a road is flooded.
- Sensor readings are generated by code and are never real hardware telemetry.

## Before presenting

1. Open this folder and double-click `start_aquashield.bat`.
2. Wait for the browser page at `http://localhost:8501`. Keep the black terminal window open.
3. Visit Home, Flood Risk Map, ML Model, Safe Routes, IoT Sensor Monitoring, Community Reports, and Social Videos.
4. Say “prototype/demo” for the routes, simulated IoT, formula labels, and inferred social pins. Say “manual catalog” for Instagram.
5. Internet is needed to install packages the first time, load OpenStreetMap tiles, embed public clips, and fetch live weather. Cached forecast data may be used if weather is unavailable.

The native app UI works on desktop/mobile browsers, but no Android package, cloud deployment, ESP32, Firebase, or shared report storage is included.
